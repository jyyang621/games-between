# 扫雷：规则、算法与验收

扫雷是微信小游戏合集的第五款游戏，稳定 ID 为 `minesweeper`，与 2048 一起位于大厅第二页。游戏在本机运行，分享参数 `g=minesweeper` 打开扫雷入口，不携带同一雷区或玩家进度。

## 难度与玩家操作

| 难度 | ID | 列×行 | 地雷数 |
| --- | --- | --- | --- |
| 初级 | `beginner` | 9×9 | 10 |
| 中级 | `intermediate` | 9×12 | 20 |
| 高级 | `expert` | 12×16 | 40 |

点击「翻开」或「插旗」按钮切换模式，再轻点格子；当前没有长按插旗。初始为翻开模式，旗标可在首次翻开前放置，插旗本身不会布雷或开始计时。

- 数字表示周围最多八格的地雷总数。翻开零雷格时，连通空白与相邻数字会自动展开，已插旗格保持覆盖。
- 首次翻开的格子及相邻一圈都没有雷，保证首步为零雷开局。普通随机棋盘仍可能出现必须猜测的局面，没有实现无猜题库或逻辑求解器。
- 插旗只表示玩家的判断，不自动检查对错；可再次点击取消，旗数允许超过雷数，因此「余雷」是地雷总数减旗数，可能为负数。
- 在翻开模式点击已展开的数字，周围旗数等于数字时，会展开其余未标记邻格。此快速排查称为 chord；旗插错时仍可能翻到地雷。
- 翻开全部非雷格即获胜，不要求插满旗。直接翻到地雷或错误排查触雷即失败；结束后停止输入和计时，并提供再来一局。

首次翻开后开始累计用时，各难度分别记录本机最佳用时。返回大厅、切到后台、旋转、分享、暂停或打开玩法说明都会通过宿主暂停，回来后由玩家点击继续。暂停画面隐藏棋盘内容；首步前、暂停和胜负结算不播放背景音乐。

## 模块边界

维护源码位于同级微信工程的 `src/games/minesweeper/`：

| 文件 | 职责 |
| --- | --- |
| `engine.js` | 纯规则、三档参数、确定性布雷、空白连开、旗标、chord、胜负、克隆与存档验证 |
| `index.js` | 统一模块接口、按钮动作、时间、确认弹窗、存档、最佳成绩、分享与音乐活动状态 |
| `renderer.js` | Canvas 绘制、安全区域与横竖屏布局、可读点击区域、暂停及结算覆盖层 |

注册表 `src/registry.js` 通过工厂惰性加载模块，复用通用 `play` 图标、分页、分享和宿主生命周期。宿主没有扫雷专属规则或模型分支。三个文件均为直接维护的 CommonJS 源；没有新增 vendor、转换器或游戏构建钩子。

## 延迟布雷与规则算法

新局保存一个无符号 32 位种子，但先不生成雷区。第一次合法翻开时，收集除首格及其邻格外的所有可用位置；用 Mulberry32 生成确定性随机数，再用部分 Fisher–Yates 从可用位置中抽取互不重复的指定数量位置。种子零也是合法输入，不依赖全局 `Math.random`。同一难度、`seed` 和 `firstIndex` 能重建同一雷区；首步前插旗不改变布雷顺序，也不会排除被标旗的位置。

空白连开采用迭代队列和已访问集合，避免递归展开；遇到雷、旗或已翻开格时跳过，零雷格继续加入邻格，边界数字展开后不再扩散。每次翻开或 chord 后检查全部安全格是否已展开。旗标本身不参与胜利判定。

chord 先检查目标已翻开、对局仍进行中和周围旗数相等，再处理其余未翻开且未插旗邻格；若这些位置存在雷，记录一个爆炸位置并判负。规则核心保存实际状态，结算时由渲染层展示雷区。

## 存档、兼容与切换难度

独立存档键为 `games-between:minesweeper:save:v1`，由公共 `saveKey('minesweeper')` 生成。外层数据格式为：

```js
{
  version: 1,
  round: { /* version 1：难度、维度、雷数、seed、雷区、已翻开、旗标、状态、用时、首步及爆炸位置 */ },
  bests: { beginner: null, intermediate: null, expert: null },
  mode: 'reveal' // 或 'flag'
}
```

三档最佳用时分别保存，但当前棋盘只有一个槽。换难度或重开会替换当前棋盘并保留最佳用时；进行中且已有首次翻开或旗标时，先弹出确认。取消后保留棋盘并处于暂停，手动继续即可；空白未操作新局和已结束对局可直接重开。异步确认使用代际标记，返回、切换或后续动作使旧回调失效，避免迟到确认覆盖新进度。

恢复时不只相信数组形状：

- 外层与棋盘版本必须为 1，难度、行列和雷数必须与固定配置完全一致。
- 种子必须为 uint32，数组必须为指定长度且每项都是布尔值；同格不能同时已翻开与插旗。
- 未开始局面必须无雷、无翻开、零用时，首步和爆炸位置为 `-1`。
- 已开始棋盘必须具有合法且已翻开的首步位置；按 `seed + firstIndex` 重算雷区，与保存的雷区逐格比对。
- `ready / playing / won / lost` 必须与已展开格、完成状态和爆炸位置一致，非法数值或矛盾终局被拒绝。
- 控制器的计时上限为 `MAX_TIME = 31,536,000,000` 毫秒（365 天）；恢复用时超过此上限时拒绝该棋盘，避免续玩后倒退。各档最佳值也只接受此范围内的有限非负数。

损坏或不兼容棋盘改建初级新局；外层版本兼容时，仍可保留合法的各档最佳用时。不兼容版本没有跨版本迁移承诺。有效的未结束存档以暂停状态恢复，已结束棋盘保留结果。游戏动作与宿主保存节点自动写入；读写失败不阻断新局，界面提示暂无法存档。各游戏原存档键和旧分享保持不变。

## 时间与共享音乐

模块仅在未暂停的 `playing` 状态接收有效正数 `deltaMs` 并累计用时，最多到 `MAX_TIME`；首步前、暂停和终局均不增加时间。继续操作由玩家触发，不补算后台离开时长。

`musicActive` 仅在未销毁、未暂停且 `round.status === 'playing'` 时为真。扫雷复用宿主唯一的原创背景音乐播放器，没有单独创建音轨或改动音乐偏好键。详细边界见 [背景音乐说明](background-music.md)。

## 限制与下一步

高级棋盘在短屏和横屏上会缩小格子，以完整容纳全部 12×16 格；当前没有缩放或拖动放大，密集棋盘的手机触控体验仍需实机评估。普通随机棋盘不保证无猜，当前没有自定义尺寸、提示、撤销、排行榜或云存档。

微信开发者工具、手机真机、真实分享与设备上的音乐听感尚未验证；未提交、推送、上传、审核或发布。本地测试和浏览器 QA 不等同于这些平台验收。下一步在微信环境检查高级密集棋盘触控、顶部安全区域、前后台与旋转、持久化、真实入口分享和音乐中断；缩放或无猜模式为可选后续产品决策。
