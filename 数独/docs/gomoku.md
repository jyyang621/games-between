# 五子棋：规则、算法与接入

五子棋是合集的第六款游戏，入口位于大厅第二页。注册 ID 为 `gomoku`，分享参数为 `g=gomoku`。微信源码直接维护在 `微信小程序/src/games/gomoku/`，沿用现有游戏契约、导航、背景音乐和平台能力。

## 玩法与交互

- 15×15 交叉点棋盘，黑棋先手，双方交替落子；横、竖、两条斜向任一连续五子及以上获胜。采用自由规则，无禁手。满盘无人获胜判和。
- 人机对战默认玩家执黑；“换先后”可改为玩家执白、电脑先行。模式旁显示“简单难度／普通难度／困难难度”，点击打开三档选择菜单；默认普通。
- 同机双人在同一台设备上轮流操作，不涉及联网匹配、房间或远程同步。
- 双人悔棋撤回一手；人机悔棋撤回最近一次玩家落子及其后电脑应手。电脑尚未应手时只撤回玩家一手；玩家执白时不能撤回电脑唯一的开局落子。终局也可悔棋。
- 落子显示最近一手标记，获胜后标明连线。电脑应手期间禁止玩家代下；暂停时棋盘不接受落子。
- 暂停、返回大厅、后台、分享和旋屏遵循宿主生命周期，回来后需手动继续。重开、切换模式、先后手或难度在进行中的非空棋盘上先确认，取消保留棋局。仅取消难度菜单或选择原难度会恢复原对局；取消换局确认后保持暂停，可手动继续。

## 规则与电脑算法

`engine.js` 是无平台依赖的纯规则模块。棋盘为 225 项数组（0 空、1 黑、2 白），棋谱保存交叉点索引。每次落子仅沿四个方向扫描两端；行列边界分别校验，避免跨行相连。终局禁止继续落子。悔棋通过重放保留棋谱重建状态。

`ai.js` 是本地 JavaScript 棋类算法，无模型 API、联网推理或远端服务。先在已有棋子周围两格内列出候选点，空棋盘选择中心。三档都会先寻找己方一步成五点，再阻挡对方一步成五点，之后才进入各自的选点策略。计算不修改真实棋局。

| 难度 | 决策方式 | 与原版关系 |
| --- | --- | --- |
| 简单 `easy` | 按连续棋子数量、两端开放程度做浅层评分；在前3个且不低于最高分72%的候选中，用棋谱哈希选一个 | 更宽松，保留基础成五与防五 |
| 普通 `normal` | 四方向五格窗口、活四、活三和复合威胁评分；进攻分＋防守分×1.08，再轻微偏向中心 | 保留原版选点行为 |
| 困难 `hard` | 在普通棋形评分基础上，用 negamax/alpha-beta 试算双方应手；最多3手（电脑→玩家→电脑） | 新增有限深度战术搜索 |

困难档每层普通候选上限为10／8／6，搜索节点预算600。一步成五与必须防守的点独立识别，不因普通候选排序被截断；己方无法立即获胜且对方有两个不同成五点时，识别为一步防不住的双杀。落子试算只更新四方向前后4格内受影响的评分，撤回试算时恢复缓存，减少重复计算。简单档使用固定棋谱哈希，同一存档重新打开不会凭空换一个随机应手。

三档仍是有界局部算法。困难档不穷举全盘，也没有保证取胜；它可以漏掉更长组合或被候选筛选排除的招法。具体战术样本的成功不能证明所有棋局或所有玩家的难度体验。对手强弱还需要玩家与真机反馈。

战术回归样本的棋谱为 `[128,142,101,157,113,172,100,158,143,174]`（从0开始的行优先索引）。普通选择127后，白126可形成110/190两个成五点；困难选择98逼白防83，再下99，形成97/102两个成五点。测试枚举这一组合中所有合法防守验证结果，说明本样本存在实际策略差异。

性能脚本 `数独/artifacts/gomoku-difficulty/ai-benchmark.mjs` 使用50个合法且双方均无直接成五点的局面，每档重复3次，共450次。2026-11-07本机Windows/Node24测得困难首次33.59ms，中位12.18ms、P95为26.46ms、重复采样最大31.20ms，数据在同目录 `ai-benchmark.json`。这只是固定样本下的桌面测量，不是手机耗时或硬实时保证。

控制器通过宿主 `tick` 累计 320ms 应手延迟，随后同步计算一手；不创建独立定时器。后台和暂停不计算，不在恢复时补下多手。延迟用于呈现轮次，不是计算耗时保证，手机性能需真机复核。

## 存档与兼容

独立键 `games-between:gomoku:save:v1`，外层 `{ version: 1, round }` 保存模式、玩家颜色、`difficulty`、棋谱和完整局面。版本与原键不变；旧存档缺少 `difficulty` 时补 `normal`，显式未知难度视为损坏。难度随悔棋、重开、换先后与模式切换保留，同机双人不使用 AI 难度。每次合法落子、悔棋或换局即保存，宿主另有生命周期保存。分享仅打开入口，不复制棋谱或强行更改接收者难度。

恢复时从空棋盘逐手重放棋谱，核对棋盘、轮次、终局、获胜者和获胜连线，拒绝重复、越界、终局后续手、不一致状态和不支持的版本。合法未结束存档恢复为暂停；损坏存档回退到新的人机棋局。读写失败不阻止游玩，界面提示存档不可用。现有游戏的键、旧分享和私有工程设置无需迁移。

| 文件 | 职责 |
| --- | --- |
| `微信小程序/src/games/gomoku/engine.js` | 规则、悔棋、快照验证 |

在仓库根目录执行（与 npm 代理调用同一套脚本）：

```sh
node 数独/scripts/build-minigame.mjs
node 数独/scripts/build-minigame.mjs --check
node --test 数独/tests/*.test.mjs
node 数独/scripts/build-minigame-preview.mjs
node 数独/scripts/serve.mjs
```

验收应覆盖大厅第二页、人机两种先后手、双人四向获胜、终局悔棋、重开确认、暂停/后台、刷新续局、存储失败、窄屏及横屏。阶段实际结果见 `docs/notion-sync.md` 和 `docs/notion-updates/`；本地回归、浏览器、微信开发者工具和手机真机分别记录，不混同。

三档难度按本次新增需求实现。下一步优先做 iOS/Android 手机真机的触控、续局、前后台、旋屏、音乐和困难档耗时验收。联网房间与更深搜索没有安排扩展承诺。
