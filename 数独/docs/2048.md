# 2048：玩法与实现

## 项目目标与实施计划

将经典 2048 作为独立的第四款游戏接入「花自飘零的游戏空间」，使用本地 Canvas 与现有宿主接口。实施分为纯规则、触控及存档、横竖屏渲染、大厅及分享接入、回归与预览验证；当前交付以这些实现及本地检查为界，微信开发者工具和真机验收仍需单独完成。

## 经典规则

- 4×4 棋盘，初始随机放置两个数字，每次数字为 2 的概率 90%、4 的概率 10%。
- 朝一个方向整体移动，去掉空隙后，相邻同值数字合并；每块在一次移动中只参与一次合并。例如 `2,2,2,2` 向左得到 `4,4,0,0`。
- 本步得分为所有合并后数字之和。只有棋盘实际改变，才增加一步并随机生成一个新数字；无效方向不消耗随机状态。
- 合成 2048 达成目标，展示本局结果；玩家可选择继续合并更大数字，或者重新开始。
- 棋盘填满且上下左右都无可合并邻居时结束；有空格或可合并邻居仍可继续。

## 模块与算法

稳定游戏 ID 为 `game-2048`，代码在同级微信工程的 [src/games/game-2048/](../../微信小程序/src/games/game-2048/)。本目录的文档、脚本及测试保留在 `数独/`，运行工程位于 `D:\怀旧小游戏\微信小程序`；以下 `src/` 路径均相对于微信工程。

- `engine.js`：纯函数规则与存档校验，不依赖 Canvas、宿主或平台。将四行或四列按移动方向提取，压缩后相邻同值两两合并，生成新的棋盘及动画来源映射，再从空格均匀选择一个位置生成数字。随机发生器使用可恢复的 uint32 状态。
- `index.js`：统一游戏接口适配、滑动手势、方向按钮、暂停/恢复、确认重开、保存、分享与短动画状态。分数更新和随机结果在有效操作时立即提交存档，动画不作为数据真相。
- `renderer.js`：奶白与森林绿界面、暖色数字块；竖屏上下排列，横屏使用棋盘和侧栏。绘制分数、最佳成绩、步数、四向按钮和结果面板。
- `src/registry.js`：唯一注册入口，工厂懒加载；第四游戏进入大厅第二页。大厅使用数字方块图标，宿主和平台没有新游戏专属分支。

每次规则操作仅扫描固定 16 格，时间和空间均为 O(16)。动画记录每个原方块的来源/目标、合并位置及新生方块；移动期间短暂锁定下一步输入，避免同一手势连触发多步。动画完成、暂停或布局变化时释放临时效果，不另建游戏计时器。

## 操作与生命周期

棋盘内单指起滑，松手后依据主轴判定方向；位移至少 18 逻辑像素，主轴至少为另一轴的 1.2 倍。轻触或明显斜滑不移动，多指和取消事件清除本次手势。可点四向按钮获得同一规则结果，不要求浏览器键盘事件或微信外部依赖。

返回大厅、后台、分享、旋屏及玩法弹窗暂停并清理手势，动画直接收束到已提交棋盘。重新打开存档时暂停，需点“继续游戏”。重开未结束且已有步数的棋盘需确认，取消后保留局面；最佳成绩一直保留。弹窗回调有代次和销毁检查，过期确认不会覆盖后来的游戏。

## 存档与兼容

新增 key 为 `games-between:game-2048:save:v1`，结构 `{ version: 1, round, best }`。round 包含 `board[16]`、`score`、`moves`、`rngState`、`won`、`keepPlaying`。仅保存规则状态和本机最佳，不存动画、触点或平台对象。

恢复时严格校验棋盘长度、数字是否为 0 或安全的 2 次幂、分数/步数非负安全整数、uint32 随机状态与布尔标记。无效局面重新开局，合法最佳成绩保留；存在 >=2048 方块时归一化获胜标记，防止无意漏掉胜利。写入失败不阻断游玩，界面显示存档提醒。

原数独、矿工和 Zuma 的 key、schema 与旧分享均保持原样；2048 分享只有入口 `g=game-2048`，不传棋盘，不覆盖接收者已有进度。存档与最佳仅在当前设备，不包含账户、云端排行榜或跨设备同步。

## 验证与后续

规则测试覆盖四方向、一次合并、得分、有效/无效生块、随机恢复、胜利继续和失败判定；模块回归覆盖手势、多指、动画期间输入、存档、后台/返回/旋屏及确认重开；布局回归覆盖窄屏、胶囊安全区和横屏，预览 bundle 覆盖全部注册游戏。

阶段记录保存实际命令、数量与截图，不将历史测试数量或已有 ZIP 当作当前版本证明。后续建议是在微信开发者工具和 iOS/Android 真机上验证手势阈值、安全区、前后台、真实分享和长局可读性，再考虑体验调整；本阶段没有上传或发布。
