# 小游戏背景音乐

数独、黄金矿工、Zuma、2048 和扫雷共用用户提供的《平沙落雁》和《阳关三叠》两首配乐。游戏运行时按下表顺序轮播，第二首结束后回到第一首。背景音乐默认开启，当前尚无操作音效；独立网页数独入口保留原来的行为。

## 玩家操作与播放边界

音乐开关位于顶部微信胶囊左侧，点击区域为 44×44 逻辑像素。开关选择单独保存于 `games-between:music:settings:v1`，仅记录 `{ enabled: boolean }`，不改动各游戏的存档或成绩。新设备默认开启，播放器音量固定为 `0.4`；这不是系统音量的绝对响度，实际听感仍受设备、系统音量和静音设置影响。

宿主只在前台游戏的 `musicActive === true`、且没有原生弹窗和系统音频中断时播放。各游戏自己判断当前是否属于运行中的玩法，宿主不读取具体游戏的棋盘或规则状态。

| 场景 | 背景音乐行为 |
| --- | --- |
| 数独普通对局、整题实战正在进行；专项练习尚未完成 | 开关开启时播放 |
| 黄金矿工矿区运行、Zuma 发球对局运行、2048 对局运行 | 开关开启时播放 |
| 扫雷首次翻开后且处于未暂停的 `playing` 状态 | 开关开启时播放；首步前、暂停和胜负结算均静音 |
| 大厅、游戏菜单、暂停、结算、已结束的关局 | 暂停播放 |
| 原生弹窗或操作菜单、系统音频中断、切到后台 | 暂停播放 |
| 原生弹窗关闭或系统中断结束 | 重新检查前台玩法状态，满足条件后才播放 |
| 返回游戏或继续游戏 | 按游戏自己的恢复规则运行，满足播放条件后继续 |
| 关闭音乐开关 | 立即暂停，并保存偏好 |

整个宿主只创建一个播放器，使用 `pause()` 保留当前曲目及播放位置；继续时不会每次从头开始。五个游戏切换时复用同一播放列表，不同时启动多条音轨。当前曲目和暂停位置只在当前运行周期内保留，不另写入跨启动存档。音频加载失败或平台不支持时，不阻止游戏继续操作。

## 平台与预览

微信侧通过平台适配层创建 `InnerAudioContext`，不强制覆盖系统的静音行为。播放器本身不自动播放，由宿主的统一生命周期决定开始、暂停和销毁。支持 `onEnded` 时关闭单曲循环，由结束事件切换到下一首；旧适配器没有结束事件时降级为首曲循环。

浏览器预览通过 `数独/preview/wx-preview.js` 的 HTMLAudio 适配器播放同两份本地 MP3，并转发曲目结束事件。生成预览后运行本地服务器，使用 `/preview/` 入口进入游戏；服务器通过 `/wechat-assets/` 路由读取同级微信工程的 `assets/`，无需复制第二份配乐。浏览器可能阻止没有用户交互的音频播放；先点击进入游戏、继续游戏或音乐按钮可重新尝试。后台、弹窗和开关行为继续由相同宿主逻辑控制；预览不是微信真机播放能力的证明。

## 素材来源与维护

用户提供的原始音频保留在 `D:\怀旧小游戏\音频\`，游戏不直接读取该目录。准备脚本将两首音频转码为微信工程 `assets/audio/` 中的 MP3 运行副本，以控制包体。曲目名称、原始文件与运行副本的 SHA256、转码参数等记录在 `playlist.source.json`。素材来源为用户提供的音频文件。

两份运行副本合计 2,512,595 字节，均为 32 kbps、22,050 Hz、单声道 MP3，保留整首曲目且不裁剪。转码前用 `loudnorm=I=-20:TP=-3:LRA=11` 调整响度；MP3 编码帧使文件时长比原始音频约多 26 毫秒。具体输入、输出和信号统计以来源清单为准。

下面的命令在 `D:\怀旧小游戏\数独` 中运行。日常构建校验无需原始音频或 FFmpeg：

```sh
node scripts/prepare-background-music.mjs --check
```

需要从原文件重新准备运行副本时，指定本机 FFmpeg 可执行文件：

```sh
node scripts/prepare-background-music.mjs --ffmpeg "C:\工具\ffmpeg.exe"
```

上面的编码器路径需替换为本机实际位置。脚本读取外层 `音频/`，输出仍写入同级微信工程的 `assets/audio/`。修改配乐后同时更新运行文件和 `playlist.source.json`，不要只覆盖音频而保留旧来源数据。

原《庭间微光 / Calm Garden》的 WAV 和来源清单保存在 `数独/artifacts/audio-archive/`，不再作为当前游戏运行资源。旧 `scripts/generate-calm-music.mjs` 仅保留历史用途，当前两首配乐由 `prepare-background-music.mjs` 维护。

## 待验收范围

需要在微信开发者工具和手机微信复核实际音量、首曲至第二首再回到首曲的衔接、手机静音设置、来电等系统中断、前后台切换和 44×44 音乐开关的安全区域。浏览器还需检查首次用户交互前后的自动播放限制。构建与回归测试结果以本次完整阶段核验记录为准，不把文件校验当作真机验收或发布结果。
