## 模式、计分与关卡流程
三种玩法 `solo`、`coop`、`versus` 分别与闯关/无尽组合，构成六份独立进度。菜单记住最近选择的组合。双人是同一设备同屏操作，当前没有网络对战。
单人/合作状态流：`menu → ready → playing → result → shop → ready`。游戏中可进入 `paused`；帮助页保留返回场景并冻结物理，查看帮助后仍需手动继续。新挑战已有进度时经过 `confirm`；最终关完成进入 `complete`。进入菜单会重新建立检查点矿场，丢弃本关未完成的即时收入。
单人/合作成功时，本关收入加到钱包与累计收入；商店消费减少钱包，不减少累计成绩。带入下一关的力量和钻石增益只作用一关，下一次关间商店将其重置为未购买；未用的随身炸药可留存。闯关失败保留本关开始时检查点，无尽失败清除本次挑战的检查点与商店。
对战每轮始终计两人的独立收入；本轮收入较高者记一个胜场，相同则记平局。`scoreRound` 生成新的累计对象，包含 `totals[2]`、`wins[2]`、`draws`，不修改上一轮对象。整场最终胜者以累计收入为准，胜场只是统计。对战没有达标提前收工按钮，不开放商店；每轮完成直接保存下一轮检查点，每人重新得到 1 枚随身炸药。
对战的引擎仍会计算合计收入是否达到矿图目标，但流程按轮次结算，不因某轮低于目标而淘汰；这与单人/合作无尽失败规则不同。

无尽开始时生成一个 32 位种子，保存在本次冒险检查点中。生成器将种子与层数做整数混合，使用确定性伪随机流选择布局变体、配色，并对上部金钻做小范围坐标扰动。相同种子与层数生成相同矿图；重新挑战整个无尽旅程才换种子。
设 `i` 为从 0 开始的层索引，目标计算为：
```plain text
target = min(4800,
  1000 + floor((log2(i + 1) × 300 + min(i, 100) × 22) / 50) × 50)
移动速度倍率 = 1 + min(i, 40) × 0.02    // 最多 1.8 倍
```
无尽矿区最多 25 个物件，TNT 始终 1–2 个。难度不会靠无限堆物件或无限加快移动速度增长。生成器拒绝越界/非整数层索引与非有限种子。当前几何与爆后价值保障由固定布局设计及采样回归验证，没有运行时路径搜索或自动重生成拒绝器。

## 抓钩与碰撞算法
原始横向矿场尺寸为 1280×720。单人支点 `(640,148)`；最短绳长 38，基础最长 760；摆速 1.05 弧度/秒。横屏摆角上限左右各 75°，竖屏各 65°。钩尖半径 8；出钩基础速度 780/秒，空钩回收 960/秒，携物回收为 `520 / sqrt(重量)`，力量药水再乘 1.35；竖屏深矿场按高度增大速度比例，避免只是矿场变长而耗时失衡。
每只抓钩状态为：`swing（摆动）→ out（出钩）→ loaded（载物回收）或 empty（空钩回收）→ swing`。绳索本身不碰撞，钩尖与物件圆形碰撞。射线求交用于静态矿物的首个接触距离与瞄准提示，按实际边界、最大绳长和钩尖半径决定先抓到谁。
宿主适配层将毫秒转为秒，每帧输入最多接收 0.1 秒，以累积器按 1/120 秒推进物理。包含移动实体/TNT/精灵的矿场引擎也会把大时间步拆成不大于 1/120 秒的小步。卡顿期间超出上限的真实时间不会一次性追赶，避免一次卡顿直接丢失大量倒计时。
移动猪、含钻猪、精灵按各自左右界限往返。一个时间步内若碰到边界，会拆成多个线性运动片段并折返，保留真实碰界时刻；通过“钩尖速度减物件速度”的相对运动，求二次方程最早圆相交时刻，避免高速物体穿过钩尖却漏碰。
精灵沿水平线运动，遇到除精灵外尚未被移除/钩住的物件就挖走，不给玩家计收入；遇桶触发同一爆炸机制。抓住精灵可以阻止它后续挖矿。
单步事件时序为：规划移动分段 → 收集钩尖/精灵接触 → 按接触时间排序 → 同时刻钩尖优先于精灵、双钩按玩家 ID 排序 → 逐一处理并再次检查物件是否已被移除/钩住 → 更新未受影响物件的位置 → 扣减时间并判定结束。这样先钩住的物件受到保护，先爆炸的物件不会再被后到抓钩领取；收入仅在载物回到最短绳长时入账。
## TNT 布局、爆炸与可达性
前 20 关保留无桶原矿场；第 21–40 关与无尽含桶。桶位于局部混合大金块/钻石矿群下方间隙，基础坐标为 `x=340 或 940，y=506`，较后变体有两桶。两排高价值矿物约位于 `y=330/430`；中央、两侧与上层保留取矿方向。桶本身半径 26，桶与矿物不重叠，两个桶不形成相互连锁的横向封锁墙。
`BARREL_BLAST_RADIUS=140`，以原始 1280×720 坐标计。提示为淡红区域与虚线椭圆，瞄准且中途没有物件阻挡时加强提示；显示、爆炸动画和伤害共用同一半径与视口比例。
抓钩碰桶或精灵挖到桶时引爆。爆炸在引爆时刻读取移动实体的位置，范围内未被钩住的金块、钻石、石头、钱袋、猪、精灵等被移除，邻桶入队连锁。每桶只处理一次，避免循环连锁重复爆炸。被炸毁物不计收入，触桶抓钩转为空钩收回；已钩住并回收中的物件不受爆炸影响。
伤害判断包含物件边缘：将与爆心的横纵距离除以视口缩放比例，若还原距离 `≤ 140 + 物件半径` 则受影响。因此物件中心在圈外但边缘进入范围时也可能被毁。随身炸药与 TNT 是不同机制，前者只销毁自己钩中的载物。
可达性验收实际采样每钩 961 条射线，以首个碰撞物作为可取得物，覆盖单人、双人、横屏和竖屏。当前回归要求每只钩初始至少可直接取得 3 件高价值金钻，支点左右都有路线，至少有一件安全首抓；逐层移除前景物件后桶也能被实际触达。
爆后余量验收要求：所有桶都爆炸后，安全静态高价值金钻合计仍不少于本关目标；上层八件不受爆炸影响，精灵不会挖到这批保障储备。测试涵盖全部 20 张新固定矿图，以及 6 个种子、前 20 层和第 100/1000/1,000,000 层的无尽矿图。
这些检查保证当前采样下的几何通路与价值余量，不是“任何收矿顺序都能在 60 秒内获胜”的数学证明，也没有穷举全部 32 位种子。后续改布局、摆角、半径、移速或视口比例时必须重跑回归并补充实际时间平衡验证。
## 模块架构与渲染适配
入口是 `微信小程序/src/games/gold-miner/index.js`，它管理场景、模式、检查点、商店、按钮、触控和物理累积器，调用规则核心 `MineEngine` 和绘制器 `MineRenderer`。宿主通过注册表懒创建游戏，游戏不直接访问 `wx`、DOM 或浏览器存储。
统一模块接口包含：`id`、`frameInterval=16`、`resize`、`render`、`tick`、`activate`、`pointer`、`pause`、`save`、`enter`、`sharePayload`、`getResumeInfo`、`statusText`、`model`。工厂注入 `read/write/now`。`render` 返回带语义标签的按钮热区，宿主统一派发操作；`pointer` 处理矿区下钩和可滚动菜单。双人用屏幕左右半区区分玩家，一次输入中每名玩家最多发射一次。
分享链接只携带 `g=gold-miner`，打开该游戏本机进度/菜单；不上传矿场、钱包、对战比分或即时局面。当前 `enter()` 无额外模式跳转逻辑。
Canvas 实际屏幕坐标、安全区域与矿区世界坐标分层处理。横屏使用 1280×720 世界；竖屏世界宽 720、高度根据可用矿区纵横比计算且不少于 740。显示变换用平移加等比缩放；矿物世界坐标按支点相对位置横纵变换，保留其当前移动位置，抓钩用向量重算角度与绳长。
双钩卷扬机横屏位于世界宽的 35%/65%，竖屏为 32%/68%。旋转时保留收入、倒计时、已移除矿物、移动物当前位置和当前出钩/载物状态，并暂停让玩家确认新方向。绘制器在世界形状改变时清理旧坐标下的爆炸圈、粒子、浮字和震屏；仅显示缩放不会清动画，引擎待绘事件也同步变换。
绘制以 Canvas 路径、形状与文字实现矿物和角色图形，没有 Phaser/DOM 精灵节点运行依赖。背景纹理装饰上限 120；粒子队列上限 260、浮字上限 24、爆炸圈上限 10；同屏范围警戒显示最多两桶，避免视觉队列无限增长。暂停时爆炸圈、粒子和浮字也冻结。
