# 游戏之间 · 微信小游戏大厅

这是「游戏之间」的微信小游戏工程，首页名称为「花自飘零的游戏空间」，以游戏大厅为入口，**数独、黄金矿工、Zuma、2048、扫雷、五子棋、俄罗斯方块与华容道均可游玩**。八个游戏都在本地运行，不需要网站服务器。大厅每页三款，2048、扫雷与五子棋位于第二页，俄罗斯方块和华容道位于第三页。

华容道把2×2曹操移到棋盘下方中央出口即获胜，棋块只能四向平移、不能旋转。可点击选块后用方向按钮，也可沿直线拖动；一次移动多格逐格计步，撤销只回退最后一格。三种固定开局共享一个当前局面槽，各关最佳独立保存，切关覆盖进度前确认；没有实时提示或自动解题。规则、关卡来源和存档校验见 [华容道说明](../数独/docs/huarongdao.md)。

## 构建与检查

最终目录为 `D:\怀旧小游戏\微信小程序`。构建脚本、测试和公共文档保存在同级的 `D:\怀旧小游戏\数独`，请在该 `数独` 工作目录打开终端，需要 Node.js 20 或更高版本，无需安装第三方依赖：

```powershell
node scripts/build-minigame.mjs
node scripts/build-minigame.mjs --check
node --test tests/*.test.mjs
```

如果本机也安装了 npm，上述命令对应 `npm run build:wechat`、`npm run check:wechat` 和 `npm test`。这些 npm 命令也可在仓库根目录 `D:\怀旧小游戏` 执行，根目录会代理到 `数独` 工作目录。

构建会把同级网页版的 `../数独/js/sudoku.js` 转换为本工程的 `src/games/sudoku/core/engine.js`，并生成 `game.js`；不要手改生成文件。该引擎用于保留旧版存档和旧分享的原棋盘，网页版源码保持原样。微信新局由独立的 `logic-v1` 题库提供，评级、课堂和训练都在微信数独模块内实现。每日挑战使用 UTC+8 日期，同一天和同难度的新题可稳定复现。

`--check` 自动运行 `scripts/games/` 下的游戏校验钩子，检查数独跨平台同题与日期边界、移植核心哈希、所有已注册可玩游戏的模块接口、原生依赖和导入配置。通用检查没有固定的游戏名单。`node --test tests/*.test.mjs` 运行完整测试，覆盖数独引擎、新游戏规则、触控、存档、游戏切换与前后台生命周期。这些本地自动检查不能替代微信开发者工具与手机真机验证。

## 数独逻辑评级与技巧课堂

新题库有 259 道题，简单、中等、困难各 64 道，专家 67 道。每题都验证唯一解：简单用单数；中等增加区块和数对；困难增加三数组与 X-Wing；专家增加 XY-Wing、XYZ-Wing 和剑鱼。高一档必须通过低一档求解器停滞检查，不再按初始数字数量分档。新增 3 道完整剑鱼题，并记录候选密度、关键技巧次数和可用结构数量；在「更多 → 本题难度说明」查看。这些观察指标还不是玩家耗时预测。详细口径和验题方式见 [数独评级说明](../数独/docs/sudoku-rating.md)。

进入数独后，点击棋盘上方的「课堂」。先看可跳过的 4 页基础教程，或直接进入 12 项技巧课；每课可在真实棋盘上推进「条件 → 推理 → 结果」。共有 74 个已验证的训练局面，每项至少 6 个；另有基于这些局面的 148 个成立/不成立辨认变式，变式不计作新增独立局面。练习时先在「① 选依据」点支撑格，再切换「填数字」或「删候选」选择操作，最后检查答案。跟练和独立练习均可逐层提示，数字筛选帮助集中观察；不同合法结构和有效的部分删除均可通过验证。

「混合练习」隐藏技巧名，「条件辨认」检查给出的依据能否成立，「错题复习」优先重做错误或到期局面。答对后可继续观看真实推理。学习记录分别保留旧次数和不同局面首次独立通过；看过图示、提示或辨认提议后，同一局面不会再被当作首次未辅助作答。

「整题实战」从初盘完成本课对应的题目，新选题的参考路径只使用本课及前置技巧。每课草稿单独保存，点「返回课堂」恢复课程，普通对局仍保留。查看提示即记录辅助，取消应用、重开本题不会清除已看提示记录。实战分享保留同一题与课程来源；完成整题不等于证明玩家使用过目标题法。

数独的「提示」先说明再确认：有填错数字时优先指出选中的错误格，否则指出首个错误格，点击「修正此格」后按本题唯一解纠正一格；无错误时点击「应用提示」应用真实逻辑步骤。排除候选会明确反馈并高亮相关格，弹窗失败会给出重试提示。「填全笔记」继续保留已证明的候选删除；改填或擦除数字会清除依赖旧数字的证明，撤销恢复对应状态。

工具栏新增「显示答案」，未完成局首次查看先确认，再进入只读答案页；返回时保留原数字、笔记和撤销历史，不自动填满或判定通关。查看期间暂停计时与配乐，后台或旋屏后返回仍需手动继续。看过答案的本局完成不计普通或整题实战成绩，查看标记随原存档保存且不能通过撤销抹去；已完成局查看不影响既有成绩，明确重新开始新局才清除标记。

旧版存档和无版本的旧分享仍打开原题，界面显示「旧版题」；开新局使用新评级。新分享保存题库 ID 与版本。新旧成绩分开统计，课堂草稿与进度使用单独的本地存档，不覆盖正在做的普通数独。

## 新游戏接入约定

`src/registry.js` 是元信息与工厂的唯一注册来源。条目包含 `id`、`title`、`subtitle`、`icon`、`status` 和 `create(context)`；`ready` 表示可进入，`soon` 表示预告。工厂按进入游戏的时机创建实例，大厅根据目录自动分页，每页三个游戏。未知 ID 的 `getGame(id)` 返回 `null`。

`src/main.js` 只启动 `src/app/host.js`。通用宿主管理进入/返回、分享、输入、计时、前后台与最后游玩记录，`src/platform/` 封装 Canvas、安全区域和微信存储，`src/hub/` 绘制大厅。数独、黄金矿工、Zuma、2048、扫雷、五子棋、俄罗斯方块和华容道平等地位于 `src/games/<id>/`，游戏模型通过 `controller.activeGame.model` 访问，`controller.screen` 为 `home` 或当前游戏 ID。

以后接入游戏时，在 `src/games/<id>/index.js` 实现模块，只在 `src/registry.js` 加一条注册，不需要修改宿主、大厅或通用构建器。模块接收 `{ read, write, now, services }`，实现统一游戏接口；绘制返回点击区域，`home` 与 `share` 由宿主处理，其余动作使用游戏自己的前缀。模块不能直接依赖 `wx`、DOM、Phaser 或浏览器存储。完整接口和最小示例见 [架构文档](../数独/docs/architecture.md)。

各游戏应使用不同的本地存档键，并在返回大厅时保存状态、停止自己的计时或动画；进入游戏时由模块决定如何恢复。已有游戏的存档键保持兼容。新游戏可使用 `src/platform/storage.js` 的 `saveKey(id, slot, version)` 生成键。保持游戏 ID 稳定，确保后续分享入口与存档仍能找到对应游戏。网页数独的 `../数独/js/sudoku.js` 继续作为数独算法源文件，不应混入其他游戏的逻辑。

## 移植源码维护

黄金矿工的新矿区和无尽矿场会把少量 TNT 放在局部金钻矿群间，并显示爆炸范围，保留可下钩的取矿路线；爆炸毁物不计收入，已钩住的矿物保留。布置与维护细节见 [TNT 设计说明](../数独/docs/gold-miner-barrels.md)。

`vendor/zuma/` 和 `vendor/gold-miner/` 保留原项目 TypeScript 核心与来源说明，`src/games/zuma/core/` 和 `src/games/gold-miner/core/` 为其 CommonJS 产物。工程已经包含产物，导入微信不需要安装 Phaser、Vite 或 TypeScript，也不需要旁边的原项目目录。构建器会保留现有配置，并为 `vendor/` 和本说明补上上传排除项；Node 开发脚本和 TypeScript 原文件不进入微信预览/上传包。祖玛的 MIT 归属同时保留在 `src/games/zuma/LICENSE.txt`。

修改核心时，按对应 vendor 目录中的生成脚本和说明重新生成；不要只修改生成文件。适配界面位于各游戏模块内，Zuma 的 `index.js` 导出 `controller.js`，关卡、进度、快照和渲染分别由 `levels.js`、`session.js`、`state.js` 与 `renderer.js` 管理。浏览器预览构建自动跟随宿主的相对 `require` 依赖，不需要另维护模块名单。

Zuma 可选简单、中等、困难、地狱四档，球速和球数依次提高；每档的闯关与无尽分别保存进度，旧存档迁移到中等档。无尽每波轮换轨道，各档速度和球数均有上限；领先球进入轨道后段时平滑缓速，最多减速 42%。清空本波后点击才进入下一波，失败重开从第一波开始，保留最佳成绩。所有难度均有稀有万能彩球：补充弹药满足八颗普通弹药间隔后，以 4% 概率抽取，命中后作为相邻颜色参与三消。参数和维护方法见 [Zuma 关卡设计](../数独/docs/zuma-levels.md)。

## 发布前的最后步骤

小游戏 AppID 配置并完成真机验证后，才能通过开发工具上传代码版本，再到[微信公众平台](https://mp.weixin.qq.com/)完成账号当前要求的资料、版本审核和发布。具体要求请以你账号后台和[微信小游戏官方文档](https://developers.weixin.qq.com/minigame/dev/guide/)为准。正式发布后才会有供朋友进入的小游戏入口；上传体验版时，也需要按平台规则添加体验成员。

工程配置参考微信团队的[小游戏快速启动模板](https://github.com/wechat-miniprogram/miniprogram-game-quickstart)与[官方小游戏示例](https://github.com/wechat-miniprogram/minigame-demo)。
