# 微信数独逻辑评级与专项素材

网页版 `js/sudoku.js` 的确定性出题和旧分享链接保持原样。微信端的新局从 `logic-v1` 离线题库选择；只有真实通过指定逻辑求解器的题目才能入库。题库由本项目原有生成器自行产生，没有引入外部题目数据。

微信端的 `state.js` 保留旧版 v1 行为，用于旧存档和没有版本标记的旧分享；新增 `rated-state.js` 的 `RatedSudokuGame` 管理新版 v2 对局。v2 存档保存 `schemaVersion: 2`、`bankId`、`ratingVersion` 和可重新验证的推理记录；v2 分享携带 `v=2` 与 `b=题目ID`，通过 ID 恢复同一初盘，而不重新用旧版的已知数数量生成。旧题不自动套用新评级，开新局才使用新题库。

## 评级口径

| 等级 | 可使用的技巧 | 入库约束 |
| --- | --- | --- |
| 简单 | 唯一候选数、唯一位置 | 仅用这些技巧完整解出 |
| 中等 | 以上，加宫指向、行列占位、显性数对、隐性数对 | 简单求解器停滞，本档完整解出 |
| 困难 | 以上，加显性三数组、隐性三数组、X-Wing | 中等求解器停滞，本档完整解出 |
| 专家 | 以上，加 XY-Wing、XYZ-Wing、剑鱼 | 困难求解器停滞，本档完整解出 |

所有题目都要满足唯一解。已知数数量只是素材来源参数，不参与最终难度判定。评分保留最高技巧、步骤数量、技巧频次与分数供后续校准，不把当前技巧集合不能解完的题称为“专家”。分数是本引擎的内部步骤权重，不是 Sudoku Explainer 分，也未宣称已经通过真实玩家耗时校准。

这里的“需要该技巧”严格指当前版本、固定扫描顺序和前置技巧集合；不是关于所有可能人类解法的数学证明。扫描顺序、技巧实现或评分规则变化时应更新 `ratingVersion`，保留老题 ID 以及对应的版本化数据，避免已分享题目改变。

## 生成与复核

以下命令在 `D:\怀旧小游戏\数独` 中运行；网页算法源仍为本目录的 `js/sudoku.js`，微信题库、逻辑模块及生成产物位于同级 [微信小程序工程](../../微信小程序/README.md)。外层目录改名不更改题库 ID、存档 key 或旧分享规则。

```powershell
node scripts/build-sudoku-bank.mjs --count=64 --training-count=6 --swordfish-count=3 --max-attempts=20000
node scripts/build-sudoku-bank.mjs --check
```

生成器有明确搜索上限，每 100 次保存断点；达到上限后可重复运行继续搜索。已有题库只追加，`--fresh` 覆盖已有题库会被拒绝，避免已发布的题目 ID 失效。未达到标准的素材不会用较简单的题目补档。运行时仅对已验题库做稳定哈希选择，不扫描随机种子，也不在手机上批量做唯一解检查。

当前随代码提供 259 道已评级整题：简单 64、中等 64、困难 64、专家 67。专家新增 3 道参考路径真实用到剑鱼、能完整解出且困难档求解器停滞的题目。另有 74 张专项卡：指向排除、显性三数组各 7 张，其余 10 项各 6 张。原 256 道题和 36 张卡的 ID、题面、候选与推理轨迹保持兼容。

整题按不同初盘计数，专项卡按技巧局面计数；一个源题可以产生不同技巧的局面。同技巧卡来自不同生成源题，没有用旋转、镜像、数字置换扩充数量。新增规范签名检查数字置换与方形的八种旋转/镜像（D4）；259 题在此范围内互不等价。这不是完整数独同构去重，尚未涵盖宫带、宫栈及内部行列的全部置换，不能宣称已证明全部题目结构独立。

覆盖检查按形态验收：唯一位置、显隐性数对与三数组都包含行/列/宫；区块排除包含横/竖、两格/三格依据；X-Wing 与剑鱼都包含横竖两种方向。完整题与训练卡分别统计，不能用专项卡数量替代整题中该技巧的覆盖数。

`--check` 对整库重新验证唯一解、正确解、最高技巧档次、低一级求解器停滞，以及专项题完整推理重放。脚本会输出实际题目和专项卡数量。

`npm run check:wechat` 的数独检查钩子在验证旧引擎跨平台同题与北京时间后，调用同一份只读题库检查。普通 `npm run build:wechat` 仍只生成小游戏入口和原有引擎适配，不重新搜索题目；导入 `checkBank()` 也不会启动 CLI 或触发生成。

## 专项题

训练卡截取自真实唯一解题目的逻辑解题轨迹。每张卡存储当前完整棋盘、81 个候选 bitmask、目标步骤、原题 ID 和轨迹下标。不是根据最终答案人工删候选，也不是无实际作用的示意图。

截取时，目标技巧之前的前置技巧全部不可用；该步骤必须产生有效填数或候选删除。候选删除会贯穿后续步骤保留，不能重新生成原始候选而丢失推理。每种技巧的训练卡来自不同生成种子；数字置换和旋转不计作独立结构。

候选 `mask & (1 << (digit - 1))` 为真表示该格仍允许该候选。`0` 表示该格已经填数。可用 `logic.js` 的 `createLogicState`、`validateStep`、`applyStep` 验证玩家提交的支撑结构与行动；允许另一种有效结构，以及有效删除集合的非空子集，避免只接受预存答案。

## 数据接口

`src/games/sudoku/bank.js` 提供 CommonJS API：

- `selectPuzzle(seed, difficulty)`：确定性选题，返回完整数组和逻辑评级元数据。
- `getPuzzle(id)`：通过稳定题目 ID 恢复原题，未知 ID 返回 `null`。
- `getTrainingExamples(techniqueId)` / `getTrainingExample(techniqueId, index)`：返回带当前候选状态的训练题。
- `getTrainingSource(id)`：取训练源题，便于重放和审计。
- `getBankSummary()`：实际各档、各技巧数量以及版本。
- `getPuzzlesByTechnique(id, options)` / `selectPuzzleByTechnique(seed, id, options)`：选择参考路径含目标题法的整题；没有匹配时返回空数组 / `null`，不偷偷换成其他技巧。`allowedTechniques` 限定完整参考路径的技巧集合；`excludeId` 在存在其他题时避开当前题。
- `getCoverageSummary()`：各技巧、行列宫、横竖及支撑格数量覆盖与去重范围。
- `getProfileSummary()`：各档观察与推理量分布。

所有返回对象都是独立拷贝，调用者的填数和笔记不能改动题库原始数据。

## 观察与推理量

`experience-v1` 是附加画像，不改动原有 `logic-v1` 评级或扫描顺序。每道题的 `experienceProfile` 记录参考路径最高档技巧次数、候选密度、有效删除次数/数量，以及每个局面当前最低技巧档可用结构数量的最小值、平均值和最大值。

“可用结构”可能包含不同区域对同一个填数的证明，不能当成独立答案数量；“最高档技巧次数”在简单档包含所有单数步骤。这些是固定参考路径的观察指标，不是 SE 分、最短解证明、全部路径依赖深度或真实玩家耗时预测。微信端可通过“更多 → 本题难度说明”查看。当前仍采用四档，尚未用未经校准的阈值追加星级。

## 笔记与菜单交互

微信数独的“填全笔记”是可切换操作：首次点击补全当前合法候选，按钮高亮并显示“取消填全”；再次点击恢复原来的手动笔记，保留之后填入的数字。期间的手动笔记编辑会同步到备份，填数与逻辑提示只清理相应格和相应候选；取消保留其余手动笔记，不额外纠正原本手动记错的候选。已验证的逻辑排除仍会应用。填全和取消各占一个撤销步，撤销不会回退计时与提示次数。内部 `fillAllNotes()` 仍用于重算，按钮通过 `toggleFillAllNotes()` 切换。

原有 v1/v2 对局与历史快照增加可选的 `fillNotesActive`、`notesBeforeFill` 字段，存档键和 schema 不变。恢复缺少字段的旧档时，只有笔记恰好等于当前完整且非空的合法候选才推断已填全（此前手动笔记无法恢复，取消后为空）；其他旧档按未开启处理。逻辑排除证明始终独立验证，取消填全不会让已证明排除重新出现。

“更多”菜单保留游戏规则、重新开始本题、冲突提示、关联高亮、查看成绩、本题难度说明共六项；返回大厅使用页头按钮。六项上限来自微信原生接口，预览适配层也检查该约束。菜单失败时给出反馈，正常取消保持安静；短屏底栏避开底部安全区。

## 提示与答案查看

微信数独的「提示」先给出说明，再由玩家确认。棋盘有填错的数字时，优先指出当前选中的错误格，否则选择首个错误格；点击「修正此格」后按本题可信的唯一解纠正一格。这是答案纠错，不伪称从错误棋盘推出的逻辑步骤；修正计为一次提示并可撤销。没有填错数字时，继续展示真实逻辑推理，点击「应用提示」才应用。排除候选的步骤会明确告知删除内容并高亮相关格，不保证每一步都直接填入数字。弹窗失败会提示重试，确认按钮文字遵守微信原生接口限制。

工具栏的「显示答案」打开独立的只读对照页。未完成局首次查看前先确认；查看不会填满棋盘或自动通关，返回后原来的数字、笔记和撤销历史保持。答案页暂停计时与背景音乐；若期间切到后台或旋转屏幕，返回原棋盘后仍保持暂停，由玩家手动继续。

未完成局确认查看后记录 `answerViewed`，本局之后完成不计入普通对局或整题实战成绩；撤销、退出与冷恢复不会抹掉该标记。已经完成的局再查看答案，不追溯取消先前成绩。明确重新开始建立新局时才清除当前局的查看标记。原 v1/v2 schema 和保存键不变，存档只增加可选布尔字段，旧存档缺省为未查看；该字段独立于可撤销的棋盘快照。

## 课程与实战

课堂提供四页可跳过的基础教程：规则、最后一格、候选数、宫与行列扫看。12 项技巧保留原 ID；棋盘图解按“条件 → 推理 → 结果”逐步展示，练习可筛选单个数字。翼形区分枢纽与两翼，鱼形区分基准线与交叉线；没有 `units` 的单数和翼形也能显示第一层观察范围。

专项练习支持跟练、独立、隐藏技巧名的混合练习，以及依据成立/不成立辨认。74 个局面各有正反两种提议，共 148 个辨认变式；变式不计作新增独立题目。辨认题保留完整可信棋盘与候选，只改变提议的依据，不能随意修改候选制造不可能局面。完成后可以继续观看后续逻辑步骤。整题实战从初盘开始，新选题的参考路径含对应技巧、且只使用本课与前置技巧，允许玩家采用其他正确解法；完成整题不等于证明玩家使用过目标题法。

整题实战使用 `games-between:sudoku:full-practice:v1`，按课程分别存草稿；普通对局仍使用原保存键。返回课堂保留两边进度。实战分享在 v2 同题链接上附 `fp=技巧ID`，接收方验证本题参考路径确实含该技巧后打开同一实战题；如果会替换该课已有的未完成填写或笔记，先确认切换，取消则保留原界面与草稿。已查看提示即记录辅助，即使取消应用或重开同题也不会恢复无提示资格。

学习记录保留旧活动次数，另按可信局面与题目 ID 记录首次作答、提示和错误、不同局面独立通过、辨认结果、复习及整题完成。图示和辨认对同一源局面的曝光也会记录，不能看过再刷首次独立信用。新训练存档兼容旧版草稿；复习间隔属于本项目的产品规则，不能宣称已通过教学研究验证。所有进度保存在当前设备。基础分享进入教程，混合/复习分享进入接收方的混合练习；辨认分享保留可信提议 ID，普通专项分享保留局面 ID。
